PostgreSQL (AWS RDS)
~$300/mo
Primary relational store for users, sessions, care briefs, medication records, audit events. Multi-AZ. Encrypted at rest with AWS KMS. PITR enabled. Row-level security for multi-tenant health system data.
Why Postgres: Row-level security is critical for multi-tenant health systems. JSONB handles variably-structured EHR payloads. Battle-tested for healthcare with excellent audit tooling.
HIPAAAES-256Multi-AZ
Redis (ElastiCache)
~$120/mo
Session caching, rate limiting, conversation state for active SMS and voice threads. Holds context across multiple patient messages without a DB round-trip. Cluster mode with encryption in transit.
Why Redis: SMS and voice conversations are stateful. Redis keeps response latency under 500ms - critical for voice interactions where delays feel unnatural to the patient.
AWS SQS + SNS
~$80/mo
Message queuing for async AI processing jobs, notification fanout to pharmacists and physicians, dead-letter queues for failed deliveries. Decouples patient intake from AI processing.
Why queuing: If the Claude API goes down, patient messages don't get lost - they queue. This is table stakes for healthcare reliability. Also critical for voice call transcription jobs.
AWS S3 + Macie
~$200/mo
Object storage for conversation transcripts, voice call recordings, clinical briefs, audit exports. Macie provides automated PHI detection across all buckets. Lifecycle policies for 7-year HIPAA retention.
Why Macie: HIPAA requires knowing where PHI lives at all times. Voice call transcripts contain PHI - Macie catches unexpected PHI leakage automatically.
Voice transcripts7yr retention
Snowflake (H2+)
~$200/mo H2
De-identified analytics warehouse. Separate from operational Postgres. Powers Vera Intel in H3. PHI never enters Snowflake - de-identification enforced at pipeline boundary. Start loading from day one.
Why separate: Analytics queries on operational data tanks performance. The separation also enforces the PHI boundary - Vera's population health data stays clean and auditable.
Vera data layerNo PHI

~$2,000/mo
Aevo's core translation engine. Claude Sonnet 4.6 for production - patient message interpretation, symptom extraction, clinical brief generation, multi-turn conversation, benefit-grounded responses. Claude Haiku for urgency pre-scoring (fast, cheap, runs on every message).
Why Claude: Best-in-class structured clinical output. Constitutional AI reduces hallucination risk on clinical claims - critical for healthcare. Anthropic offers BAA-compatible enterprise agreements. Sonnet 4.6 is the current production model.

~$400/mo
Secondary LLM for redundancy and A/B evaluation. Text-embedding-3-small for semantic similarity in Vera's consistency checking. If Claude API degrades, patient messages still process. Never a single point of AI failure.
Why a fallback: Healthcare requires 99.9%+ reliability thinking. Having a fallback isn't a preference - it's a clinical safety requirement for a system patients depend on.
LangChain / LangGraph
Free (OSS)
Orchestration layer for Aevo's multi-step pipeline: intake → extraction → knowledge lookup → brief generation → urgency scoring. LangGraph manages stateful conversation graphs for multi-turn SMS and voice flows.
Why orchestration: The AI pipeline has 7+ steps with branching logic. Orchestration makes each step testable and swappable - replace the LLM provider without rewriting business logic.
LangSmith (Vera drift monitoring)
~$400/mo
LLM observability for Vera - trace every AI call, log inputs and outputs, monitor latency, track token usage. Weekly automated evals against a golden test set of 500 validated clinical conversations. Vera's drift detection lives here.
Why observability: In healthcare, you must explain every AI output to an auditor. LangSmith provides a full trace for every brief ever generated - critical for liability defense and HIPAA alignment.
VeraDrift detection

~$400/mo
Vector database for Vera's clinical knowledge base - drug interactions (First Databank), dosing guidelines, symptom-condition mappings, benefit structures, SDoH resource data. Semantic search grounds every Aevo output in verified information.
Why RAG: An LLM making ungrounded clinical claims is a liability. RAG ensures every drug interaction statement cites a source. Vera validates every RAG-grounded claim before delivery.

Vanta
~$1,200/mo
SOC 2 Type I and II automation. HIPAA risk assessment. Vendor management. Continuous control monitoring across AWS, GitHub, Vercel, and every connected tool. Generates audit-ready reports. Fastest path to SOC 2 Type I in 4-6 months vs. 12-18 months without it.
Why Vanta first: Without Vanta or Drata, SOC 2 is 12-18 months of manual work. With Vanta, Type I in 4-6 months. This is the single highest-ROI compliance spend - it unlocks every health system pilot conversation.
Must-have H1SOC 2 Type I
Auth0 / Okta
~$600/mo
Authentication for all user types: patients (SMS OTP + app biometrics), pharmacists (SSO + MFA), physicians (SSO + MFA), admins (hardware MFA). HIPAA-eligible. Role-based access control with audit logging. NPI-verified roles for care team members.
Why not build auth: Authentication bugs are the leading cause of PHI breaches. Auth0 has been penetration-tested by thousands of enterprise customers. Don't build this wheel - it's a liability surface, not a product differentiator.
NPI role verificationHIPAA
AWS Secrets Manager + KMS
~$200/mo
Central secrets management for all API keys - Twilio, ElevenLabs, Deepgram, Claude, Epic tokens. Automatic password rotation. KMS for envelope encryption of all PHI fields. No secrets in environment variables or code - SOC 2 requires this.
Why secrets manager: ElevenLabs API key, Claude API key, Twilio auth token - if any of these leak, the blast radius is significant. Secrets Manager with rotation closes this surface and satisfies the SOC 2 control automatically.
HackerOne + Burp Suite
~$1,000/mo
Annual penetration testing via HackerOne managed bug bounty. Quarterly automated scanning with Burp Suite Enterprise. Health system procurement requires a recent pen test report from a recognized firm - this is the difference between a signed pilot and a passed one.
Why pen testing at seed: Every health system you approach will ask for your most recent pen test report. "We haven't done one yet" ends the conversation. One pen test report from a recognized firm unlocks all three pilots.
Pilot requirement
Datadog SIEM
~$500/mo
Security information and event management. Detects anomalous access patterns, generates HIPAA audit logs, alerts on bulk PHI export or off-hours access. HIPAA's breach notification rule requires fast detection. Without SIEM you may not know you've been breached until it's too late.
Why SIEM at seed: The 60-day HIPAA breach notification clock starts when you discover the breach - not when it happened. SIEM compresses discovery time from weeks to hours.

dbt + Airbyte
~$300/mo
Vera's data pipeline. Airbyte syncs de-identified interaction data from Postgres to Snowflake. dbt transforms raw events into clinical outcome models - adherence rates, ADE prevention scores, SDoH resolution rates, voice interaction quality. The foundation of Orivo Intel in H3.
Why build the pipeline now: Orivo Intel requires 18+ months of clean structured data. Start the pipeline in H1 and you arrive at Series B with a real dataset. Not starting now means arriving at Series B with a promise instead of proof.
Vera Intel foundation
Mixpanel
~$200/mo
Product analytics for the Orivo app and Brief dashboard. Track conversation completion rates, voice call durations, SMS response times, brief open rates, pharmacist acknowledgment times. HIPAA-eligible with BAA. Drives AI prompt improvement directly.
Why Mixpanel: Funnel analysis shows where patients drop out of the care conversation. Voice call drop-off points show where ElevenLabs audio needs adjustment. This data directly improves adherence outcomes - your core pilot metric.
Metabase

Why both: Sentry catches code errors. Datadog catches performance degradation. A patient reporting chest pain needs a response in seconds - both types of failure must be caught independently and immediately.
