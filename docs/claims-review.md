# Claims Review

## Public Positioning

Orivo should be positioned as a prototype or pilot-stage SMS-first medication communication layer.

## Terms To Prefer

- SMS-first medication support
- Patient-language translation
- Pharmacist review brief
- Human-in-the-loop routing
- HIPAA-conscious architecture target
- HIPAA-aligned design target
- Synthetic demo data
- Prototype workflow

## Terms To Avoid Until Validated

- HIPAA compliant, unless reviewed by counsel and supported by actual controls and BAAs
- Proven adherence lift
- Proven ADE reduction
- Any patient, any country, any insurance
- Only dataset in existence
- Recommends medication switches
- Diagnoses ADEs
- Confidential prototype, unless access control exists

## Demo Rule

All demo scenarios should be treated as synthetic examples. No protected health information should be entered into the static GitHub Pages site.

## Static Site Boundary

The public GitHub Pages site should not collect patient intake details, symptoms, medication lists, insurance information, date of birth, SSNs, or live clinical messages.
