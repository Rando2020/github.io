Engineering approach

Built boring
on purpose.

In a clinical-adjacent system, the impressive move is restraint. Orivo's prototype stack is small, inspectable, and gated — because the first real patient message deserves infrastructure that can be audited, not admired.

What you won't find here: cost projections, patient-volume forecasts, or a list of enterprise services we haven't deployed. This page describes what exists, what's required before a live pilot, and what gets built at each milestone — in that order.
Prototype inventory

What exists today.

A deliberately small footprint: enough to run a real non-PHI SMS workflow end to end, and nothing that would need to be un-built later.

Built

SMS webhook handler

Inbound message endpoint for Twilio with request signature validation on every call — spoofed webhooks are rejected before any processing happens.

Built

Deterministic triage engine

Keyword and pattern rules that classify each message into a response tier. Every classification is reproducible and inspectable — see it traced on the Aevo + Vera page.

Built

Bilingual message templates

Pharmacist-reviewable response templates in English and Spanish. Templates are versioned so a pilot's approved language is a fixed, auditable artifact.

Built

Human approval queue

The structural gate: clinical-tier drafts enter a review queue and cannot reach a patient until a pharmacist releases them. There is no bypass path in the workflow.

Built

API + data layer

FastAPI service with a lightweight database for prototype work. Small on purpose: the non-PHI prototype doesn't need — and shouldn't have — production PHI infrastructure it can't yet justify.

Built

Consent + STOP handling

Opt-in state tracking with immediate STOP compliance and HELP responses, designed to the TCPA healthcare-messaging consent template from day one.

Operating principles

Four rules that shape every build decision.

Auditable beats impressive

Deterministic triage over a language model, versioned templates over free generation, append-only logs over mutable state. Anything a pilot partner's compliance reviewer asks about should have a line-by-line answer.

Complexity is earned by milestones

Infrastructure gets added when a milestone requires it — not when a funding round makes it affordable. A component that exists before its workload is a liability with a monthly bill.

The patient's phone sets the constraint

Everything is designed backward from a basic phone on SMS. No app, no portal, no login, no smartphone assumption — because the populations Orivo serves are exactly the ones those assumptions exclude.

Human approval is load-bearing

The pharmacist review queue isn't a feature that could be deprioritized — it's the architecture the rest of the system hangs on. See how it's enforced on the Aevo + Vera page.

Sequencing

What gets built when — tied to milestones, not fantasies.

Each stage adds only what the next milestone demands. Capability sequencing is published here; costs and forecasts are not, because published numbers should be earned numbers.

Stage 1 · Now
Discovery & validation

Prove the workflow on synthetic data

  • Non-PHI prototype exercised end to end
  • Triage rules tested against a growing synthetic message set
  • Consent and template language reviewed with pharmacists during discovery interviews
  • Pilot scorecard instrumentation defined before the pilot, not after
Exit: a pharmacy partner signed and gates 2–6 in motion.
Stage 2 · First pilot
One pharmacy · live patients

Harden for PHI, keep the footprint small

  • BAA-covered messaging and HIPAA-eligible hosting (gates 3–5 cleared)
  • Production database with encryption and backups replacing the prototype store
  • Append-only audit log for every message, classification, approval, and send
  • CSV roster enrollment tooling for the pharmacy — integration-free by design
Exit: 90 days of honest scorecard data from real patients.
Stage 3 · After proof
Multi-site · payer conversations

Expand only what the data justifies

  • Multi-pharmacy tenancy and role-based access
  • LLM-assisted drafting introduced behind the existing approval gate — the gate stays
  • Standards-based integrations (pharmacy systems, FHIR) as partners require them
  • Additional languages and voice channels driven by pilot population needs
Exit criteria set with partners — not preannounced here.
